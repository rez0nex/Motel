# Технические решения Motel

Решения из доступной истории и текущего кода; даты их принятия не установлены, кроме явно указанных. Мелкие правки ведутся в журнале.

## Среда и зависимости

Использовать установленную Unity **6000.6.7f1**, подключённые Input System **1.20.1** и URP **17.6.0**. Не добавлять сторонние зависимости для первого прототипа: необходимых средств уже достаточно в проекте. Материалы генератора используют URP/Lit.

## Управление и ввод прототипа

Ходьба и гравитация выполняются через CharacterController; прыжок и бег не входят в первый этап. Действия Input System задаются отдельной картой в коде: шаблонный Interact использует удержание, а прототипу нужно одиночное нажатие E. Это сохраняет исходный Input Actions asset без изменений.

Освобождённый курсор отключает ходьбу, обзор и взаимодействие. Гравитация и анимация двери продолжаются; для возврата управления нужен клик. Так можно работать с редактором, не управляя персонажем.

## Взаимодействие и дверь

Луч идёт из центра камеры до 2,5 м и учитывает первое твёрдое препятствие. Проверка всех препятствий сохраняет блокировку взаимодействия стенами. Игрок находится на встроенном слое Ignore Raycast, чтобы не перекрывать собственный луч.

Дверь использует кинематический Rigidbody на петле и дочернее полотно с BoxCollider. Поворот выполняется через MoveRotation в FixedUpdate: точка вращения находится на краю полотна, а дверь участвует в столкновениях.

## Создание сцены и интерфейс

Тестовую сцену создаёт отдельный Editor-инструмент с фиксированным путём `Assets/Scenes/Prototype.unity`. Вместо добавления объектов в существующую сцену он создаёт новую; перед перезаписью требует подтверждения и повторно использует материалы. Это упрощает воспроизведение прототипа и сохраняет SampleScene. Поведение генератора ещё требует проверки в Unity.

Прицел и подсказки используют встроенный IMGUI, чтобы не требовать дополнительных UI-ресурсов для этого этапа.

## 2026-10-30 — ветки разработки и сохранение этапов

Разработка ведётся в `dev`, законченные этапы сохраняются отдельными осмысленными коммитами после проверки изменений и обновления документации.
