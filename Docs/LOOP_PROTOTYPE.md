# Петля, авария и одно наблюдение

Инструкция исходного этапа петли `01bf0b8` поверх принятой планировки `5aafabe`. Сцена — **Assets/Scenes/MotelBlockout.unity**. Тогда добавлены часы/пауза/авария/сброс, один факт и простые окна. Текущий следующий эпизод с Леонидом описан отдельно в [LEONID_EPISODE.md](LEONID_EPISODE.md); он добавляет второй факт, не отменяя проверки ниже.

## Запуск и создание

1. В Unity **6000.6.7f1** дождаться окончания импорта без ошибок Console. Открыть сохранённую **MotelBlockout**.
2. Для пересоздания вне Play Mode выбрать **Motel → Create Motel Blockout** и подтвердить перезапись. Это полная воспроизводимая сборка одной сцены, без наращивания объектов; пользовательские правки сцены перед этим сохранить отдельно. Prototype и SampleScene остаются шаблонами без изменений.
3. Play → Game → клик. Игрок за стойкой, цифровые часы впереди на стойке. Обычная попытка идёт с **20:16:00 до 20:22:00 за 360 секунд активного времени**. Постоянного обратного отсчёта нет.
4. **Escape** освобождает курсор и ставит часы, двери и симуляцию на паузу; клик продолжает. Потеря фокуса также ставит паузу, без автоматического продолжения при возврате окна.
5. **J** открывает «Наблюдения»: время и управление остановлены. Повторное J или кнопка закрытия продолжает; Escape закрывает окно и оставляет игру на паузе.
6. Для быстрой проверки: Escape → **F6** → клик. Видна надпись **«ОТЛАДКА · полный цикл за 60 с»**. Идёт то же игровое время, скорость ×6; режим сохраняется между сбросами. Escape → F6 возвращает обычную скорость. Сохранённая сцена и новый запуск сборки по умолчанию используют 360 секунд.

## Маршрут ручной проверки

1. Начать в обычном режиме. Посмотреть часы, открыть дверь, нажать Escape во время её движения. Подождать: часы, полотно и игрок неподвижны. Клик — всё продолжается. Повторить с J, убедиться, что клик внутри окна не захватывает управление и не вызывает E.
2. Включить отладочные 60 секунд. Открыть несколько дверей, уйти со стартового места. В 20:22 ожидаются короткая вспышка, потускнение/изменение света, подготовленные повреждение оборудования и обломки, затем затемнение и загрузка новой попытки. E и движение во время аварии заблокированы. Escape во время перехода также ставит его на паузу.
3. После загрузки проверить старт за стойкой и взгляд на главный вход, **20:16**, закрытые двери, исходный свет, целое оборудование и отсутствие обломков. При активном окне управление возобновляется автоматически; после потери фокуса нужен клик.
4. Из-за стойки выйти через северный обход, пройти по служебному проходу к **Технической**. Открыть E, подойти к восточной стороне оборудования: небольшая кнопка под надписью **«Аварийное отключение»**. На расстоянии до 2,5 м единственная подсказка — **«E — аварийное отключение»**. Закрытые стены и двери должны перекрывать луч.
5. Нажать E. Зелёная индикация сразу гаснет, примерно через полсекунды начинается та же авария. После сброса открыть J: ровно один факт **«Отключение оборудования вызвало взрыв»**. Повторить несколько раз: факт и объекты не размножаются. При обычном ожидании таймера этот факт не выдаётся.
6. Для пограничного случая нажать кнопку около 20:22: один переход, без второго сброса следом. Окончание таймера, уже начавшее аварию, блокирует последующее вмешательство. После окончания Play Mode и нового запуска факт должен остаться. Для проверки пустого начала можно вне игры **переименовать** свой файл сохранения, сохранив резервную копию; он не хранится в Git.
7. Проверить девять окон: по одному на наружной стене каждого номера и одно на южной стене ресепшена. В доступных 2, 4, 7, 8 и снаружи видны настоящий проём, рама и прозрачное стекло. Окна не открываются и не пропускают игрока. Мебель, проход 7 ↔ 8 и оба выхода остаются свободными. Размер проёма — 1,6 × 1,1 м, подоконник на 1,1 м, верх на 2,2 м.
8. Повторить один полный обычный цикл (360 **активных** секунд), учитывая остановки Escape/J: авария только в 20:22. Проверить отмену и подтверждение пересоздания сцены вне Play Mode: одна группа **Time Loop**, один Player, один аварийный объект, девять стёкол.

## Сохранение и ограничения

Файл **observations-v1.json** находится в `Application.persistentDataPath`; для текущих Player Settings в Windows это `%USERPROFILE%/AppData/LocalLow/DefaultCompany/Motel/observations-v1.json`. Версия формата — 1, единственный факт хранится флагом и не дублируется. Новый факт записывается через временный файл и атомарное перемещение/замену; перезагрузка сцены сохраняет знания, но не состояние мира. Неизвестный формат или повреждённый файл сохраняется без перезаписи; при ошибке записи окно сообщает, что новые знания доступны только в сессии.

Разрушение постановочное: заранее созданная повреждённая модель оборудования и пять мелких обломков, без физической разрушаемости. Дверь технической не разрушается. Звук, дым, второй способ вмешательства и полный книжный журнал не реализованы. Первый эпизод NPC/эвакуации добавлен следующим этапом, см. LEONID_EPISODE.md. Чёрный переход скрывает загрузку той же сцены. Скорость F6 ускоряет часы, не ходьбу персонажа; маршрут Леонида сначала проверять в обычном режиме.

## Доступные проверки и сборка

- `powershell -NoProfile -ExecutionPolicy Bypass -File Tools/ValidateMotelBlockout.ps1` — компиляция runtime/Editor установленным компилятором Unity и проверка модели геометрии, проёмов, окон и маршрутов. Не запускает Unity.
- **Motel → Validate Loop and Observations** — проверки состояния обычного/ускоренного времени, паузы, защиты повторного запроса, сбросов, записи/загрузки одного факта и сохранения неизвестного формата; также ссылки текущей сцены. Это не ручная проверка игры. Проверка будущей версии файла намеренно пишет предупреждение, сохраняя тестовый файл в Temp.
- **Motel → Build Windows Demo** — сборка единственной MotelBlockout в **Builds/MotelDemo/Motel.exe**, без изменения пользовательского списка сцен Build Profile. Нужен Windows Build Support. Builds исключена из Git. Перед сборкой остановить Play Mode и сохранить сцену; сцену оставить в обычной скорости.

Windows x64 сборка подготовлена и запущена: просмотрен настоящий кадр Player с нормальными материалами, часами и окном. Это проверка запуска и отображения, а не ручная приёмка всего игрового маршрута. Для переноса демо копировать всю папку **Builds/MotelDemo**, включая каталог данных и библиотеки рядом с exe. Сборку и отдельную компиляцию выполнять последовательно; инструмент сборки временно ограничивает ресурсы Bee/.NET.

Фактические результаты проверок этого этапа записаны в [журнале](DEVELOPMENT_LOG.md). Полный ручной маршрут ещё не принят. По прямому запросу пользователя от 2026-10-30 итог дня сохраняется и публикуется полным Git-циклом; это не заменяет оставшуюся ручную проверку.
